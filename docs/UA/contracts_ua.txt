============================== ФОРМАТИ ДАНИХ ТА СТАНІВ ==============================


------------------------------ 8. Number B4 ------------------------------


| B4[i] | Поле | Допустимий формат   |
|-------|------|---------------------|
| 0     | Hi   | Ціле 0…99999        |
| 1     | Lo   | Ціле 0…99999        |
| 2     | Exp  | Ціле −999999…999999 |
| 3     | Neg  | 0 / 1               |

| Умова                                                | Інваріант                                                              |
|------------------------------------------------------|------------------------------------------------------------------------|
| Ненульовий канонічний Number                         | 10000 ≤ Hi ≤ 99999, 0 ≤ Lo ≤ 99999; перша десяткова цифра Hi ненульова |
| Канонічний нуль                                      | [0,0,0,0]                                                              |
| Допустима Exp для успішного арифметичного результату | -999999 ≤ Exp ≤ 999999                                                 |
| Математичне значення                                 | (-1)^Neg × (Hi × 100000 + Lo) × 10^(Exp−9)                             |
| Ненормалізований / довільний B4                      | Не є допустимим Number-входом для арифметичних функцій                 |
| Result / Operand / M / EntryNumber                   | Однаковий Number B4 контракт                                           |

Hi × 100000 + Lo вище — математична інтерпретація; фізично ціле десятизначне значення в один native scalar не об'єднується.
Для канонічного Number B4: Hi=0 ⇔ Number=0; Hi!=0 ⇔ Number!=0. Перевіряти Lo, Exp і Neg для визначення нуля не потрібно.


------------------------------ 9. Wide arithmetic B5 ------------------------------


| B5[i] | Chunk        | Межі    |
|-------|--------------|---------|
| 0     | C0, старший  | 0…99999 |
| 1     | C1           | 0…99999 |
| 2     | C2           | 0…99999 |
| 3     | C3           | 0…99999 |
| 4     | C4, молодший | 0…99999 |

| F                    | Вхідна умова / вихідна гарантія                                                                                    |
|----------------------|--------------------------------------------------------------------------------------------------------------------|
| funShift25           | Цілий shift: додатний — вправо; від'ємний — вліво; abs(shift) ≥ 25 → нульова B5; розряди за межами B5 відкидаються |
| funWideAdd25         | Беззнакові A,B B5; перенос поза 25 десятковими розрядами відкидається                                              |
| funWideSub25         | Беззнакові A,B B5; передумова A ≥ B; функція не повертає знак A−B                                                  |
| funLeadingPosition25 | Для нульової B5: p=25, zero=1                                                                                      |
| funNormalizeAddSub25 | Приймає B5 та BigExp; повертає Hi, Lo, Exp, zero; знак формує зовнішній funAddSub                                  |
| funAddSub            | Big/Small за модулем; bigShift=1, smallShift=BigExp−SmallExp+1                                                     |

Складання п'яти chunks у єдиний native 25-digit scalar не виконується.


------------------------------ 10. Entry ------------------------------


| Поле Entry | Допустимі значення | Контракт                       |
|------------|--------------------|--------------------------------|
| Hi         | 0…99999            | Перші п'ять буквальних цифр    |
| Lo         | 0…99999            | Наступні п'ять буквальних цифр |
| Len        | 1…10               | Лічить лише цифри, не знак     |
| Neg        | 0 / 1              | Знак буквального запису        |
| DotOn      | 0 / 1              | Наявність десяткової крапки    |
| DotAfter   | 0…Len              | Кількість цифр перед крапкою   |

| Інваріант                 | Умова                                                                                      |
|---------------------------|--------------------------------------------------------------------------------------------|
| Ємність дисплея           | Len + Neg ≤ 10                                                                             |
| За Neg=1                  | Len ≤ 9                                                                                    |
| За DotOn=0                | DotAfter=0                                                                                 |
| Dot                       | Не займає фізичного місця Digit                                                            |
| Нульовий буквальний Entry | -0 допускається; канонічний математичний Number ніколи не має Neg=1 при нулі               |
| Entry проти Number        | Entry.Hi/Lo не є нормальною мантисою Number і не зобов'язані мати ненульовий перший розряд |
| Базовий Entry             | Hi=0,Lo=0,Len=1,Neg=0,DotOn=0,DotAfter=0                                                   |

| Команда EntryController | Передумова                    | Оновлення                                               |
|-------------------------|-------------------------------|---------------------------------------------------------|
| 301 Digit               | SingleZero без DotOn, digit>0 | Замінити початковий 0 введеною цифрою, Len не змінювати |
| 301 Digit               | SingleZero без DotOn, digit=0 | Не додавати ще один початковий 0                        |
| 301 Digit               | Не SingleZero; Len+Neg<10     | Додати цифру праворуч, Len+1                            |
| 301 Digit               | Len+Neg=10                    | Нову цифру не додавати                                  |
| 303 Dot                 | DotOn=0                       | DotOn=1, DotAfter=Len                                   |
| 303 Dot                 | DotOn=1                       | Без зміни                                               |
| 306 ToggleSign          | Neg=0 та Len<10               | Neg=1                                                   |
| 306 ToggleSign          | Neg=0 та Len=10               | Залишити Neg=0                                          |
| 306 ToggleSign          | Neg=1                         | Neg=0                                                   |
| 307 Backspace           | DotOn=1 і DotAfter=Len        | Видалити кінцеву крапку, цифри зберегти                 |
| 307 Backspace           | Інший випадок                 | Прибрати останню цифру, Len не нижче 1, Neg зберегти    |

Для funEntryToNum обов'язкові коректні Len, DotOn, DotAfter; результат повинен відповідати Number B4 із C§8.

============================== OWNERSHIP / STATE ==============================


------------------------------ 18. State ownership ------------------------------


| State bank          | Єдиний normal writer                    | Окремий reset override                                      |
|---------------------|-----------------------------------------|-------------------------------------------------------------|
| EntryState B6       | EntryController                         | PreparationController.EntryReset через StateController      |
| ArithmeticState B11 | CalculationController                   | PreparationController.ArithmeticReset через StateController |
| MemoryState M B4    | MemoryController                        | Немає глобального reset; MC — normal worker                 |
| Mode                | StateController під час POST/ModeCommit | У runtime немає окремого reset; Clear пише 401 у POST       |

Reset override — окреме право керувати входом даних і Write тієї самої state-memory, а не додатковий normal writer.


------------------------------ 19. Command worker ownership ------------------------------


| Code               | Команда                           | Єдиний normal worker  | Bank, що змінюється                       |
|--------------------|-----------------------------------|-----------------------|-------------------------------------------|
| 301, 303, 306, 307 | Digit, Dot, ToggleSign, Backspace | EntryController       | EntryState                                |
| 302, 304, 310      | Operation, Equals, MR             | CalculationController | ArithmeticState                           |
| 308, 309, 311      | M+, M−, MC                        | MemoryController      | M B4                                      |
| 305                | Clear                             | Немає; Flow 504       | PRE reset Entry+Arithmetic, POST Mode 401 |
| Flow 501           | DROP                              | Немає                 | Без змін                                  |

| Правило                  | Контракт                                                                    |
|--------------------------|-----------------------------------------------------------------------------|
| Одна command transaction | Не більше одного normal worker                                              |
| MemoryRecall 310         | M лише читається; змінює ArithmeticState, тому не належить MemoryController |
| ERROR Mode 403           | Усі дійсні user commands, крім Clear, DROP                                  |


------------------------------ 20. Candidate / Current ------------------------------


| Bank           | Candidate                                                        | Current                              | Авторитетний вихід |
|----------------|------------------------------------------------------------------|--------------------------------------|--------------------|
| Mode           | InitMemory(401), Write=pass(modeWrite)                           | Memory, Write=NOT(modeWrite)         | ModeCurrent        |
| Arithmetic B11 | InitBusMemory(DefaultArithmetic), Write=OR(arithWork,arithReset) | BusMemory, Write=NOT(arithWork)      | ArithmeticCurrent  |
| Memory M B4    | BusMemory, Write=pass(memoryWork)                                | BusMemory, Write=NOT(memoryWork)     | MemoryCurrent      |
| Entry B6       | BusMemory, Write=OR(work,reset)                                  | BusMemory, Write=OR(NOT(work),reset) | EntryCurrent       |

| Фаза/умова                | Гарантія                                                                   |
|---------------------------|----------------------------------------------------------------------------|
| Compute Work=1 без Reset  | Candidate має право на запис; Current для читачів зберігає попередній стан |
| Work спав                 | Candidate заморожується, Current починає копіювання                        |
| До кінця CommitDelay      | Новий Current ще не оголошується завершеним для наступної транзакції       |
| Commit завершений         | Новий Current авторитетний                                                 |
| Raw ALU Error             | До Candidate передають старий Current, а не арифметично помилкові дані     |
| Звичайне оновлення B11/B4 | Цілий bank записується атомарно, не окремі поля                            |

------------------------------ 23. Operation behavior (302) ------------------------------


Позначення таблиць: R — старий Result, O — старий Operand, E — EntryNumber, op — стара Operation, newOp — B2.Value; ALU(X,Y,op) — результат потрібної арифметичної операції. P = OpPending, Q = RhsReady. = у клітинці — нове значення, same — поле без змін.

| Mode   | P | Q | Новий Result | Новий Operand | Operation | P' | Q' | ALU? |
|--------|---|---|--------------|---------------|-----------|----|----|------|
| ENTRY  | 0 | * | E            | E             | newOp     | 1  | 0  | ні   |
| ENTRY  | 1 | * | ALU(R,E,op)  | E             | newOp     | 1  | 0  | так  |
| RESULT | 0 | * | same R       | R             | newOp     | 1  | 0  | ні   |
| RESULT | 1 | 0 | same R       | same O        | newOp     | 1  | 0  | ні   |
| RESULT | 1 | 1 | ALU(R,O,op)  | same O        | newOp     | 1  | 0  | так  |

* — значення не впливає на цю гілку. Operation 302 дозволяє newOp тільки 201…204. У ENTRY normal Flow=503 змінює Mode на RESULT після завершення worker.
При арифметичній помилці SafeNextState B11 = старий Current B11, та POST переводить Mode у ERROR; незавершені поля не мають частково змінитися.


------------------------------ 24. Equals behavior (304) ------------------------------


| Mode   | P | Operation | Новий Result | Новий Operand | Operation' | P' | Q' | Наслідок          |
|--------|---|-----------|--------------|---------------|------------|----|----|-------------------|
| ENTRY  | 0 | будь-яка  | E            | E             | 200        | 0  | 0  | просто показати E |
| ENTRY  | 1 | 201…204   | ALU(R,E,op)  | E             | same       | 0  | 0  | завершити pending |
| RESULT | 1 | 201…204   | ALU(R,O,op)  | same O        | same       | 0  | 0  | завершити pending |
| RESULT | 0 | 201…204   | ALU(R,O,op)  | same O        | same       | 0  | 0  | repeated Equals   |
| RESULT | 0 | 200       | same R       | same O        | 200        | 0  | 0  | NoOp              |

При арифметичному Equals Operation та останній Operand зберігаються. При RESULT/P=0/Operation=200 команда не змінює арифметичний стан.


------------------------------ 25. MemoryRecall behavior (310) ------------------------------


| P | Новий Result | Новий Operand | Operation' | P' | Q' | Видимий Number після MR |
|---|--------------|---------------|------------|----|----|-------------------------|
| 1 | same R       | M             | same op    | 1  | 1  | Operand=M               |
| 0 | M            | M             | 200        | 0  | 0  | Result=M                |

MR не змінює M. За P=1 записує Operand=M, RhsReady=1; арифметичне застосування відкладено. В ENTRY Flow=503; у RESULT Flow=500.


------------------------------ 26. Memory behavior ------------------------------


Для M+ / M− поточне арифметичне число обирається незалежно від режиму виведення:

| Mode   | RhsReady | CurrentNumber                                                |
|--------|----------|--------------------------------------------------------------|
| ENTRY  | 0 або 1  | EntryNumber                                                  |
| RESULT | 0        | Result                                                       |
| RESULT | 1        | Operand                                                      |
| ERROR  | —        | операції M не виконуються (DROP), крім Clear, яка зберігає M |

| Команда   | Нове M            | ALU use? | Mode result       |
|-----------|-------------------|----------|-------------------|
| 308 M+    | M + CurrentNumber | так, 201 | Mode зберігається |
| 309 M−    | M − CurrentNumber | так, 202 | Mode зберігається |
| 311 MC    | [0,0,0,0]         | ні       | Mode зберігається |
| 310 MR    | same M (читання)  | ні       | див. C§25         |
| 305 Clear | same M            | ні       | Mode→ENTRY        |

У MemoryController власний екземпляр ArithmeticUnit, не спільний ALU з CalculationController. Raw memory ALU error зберігає старе M через SafeM; Sticky Error фіксується тільки після Compute.Done. При MC UseALU=0.


------------------------------ 27. Result / Operand selection ------------------------------


| RhsReady | Number для ResultRenderer / Fits | Number для MemoryController у RESULT |
|----------|----------------------------------|--------------------------------------|
| 0        | Result B4                        | Result B4                            |
| 1        | Operand B4                       | Operand B4                           |

Цей вибір не залежить від OpPending. У ENTRY для M+/M− CurrentNumber — EntryNumber, а не ResultNumberSelector.


------------------------------ 28. Display selection ------------------------------


| Mode           | ResultFits | Output Frame   |
|----------------|------------|----------------|
| 401 ENTRY      | —          | EntryRenderer  |
| 402 RESULT     | 1          | ResultRenderer |
| 402 RESULT     | 0          | ErrorRenderer  |
| 403 ERROR      | —          | ErrorRenderer  |
| Невідомий Mode | —          | ErrorRenderer  |

Values B10 і Dots B10 обираються від одного й того самого Renderer; змішувати Frames між гілками заборонено. ResultRenderer.Fits передається також у StateController для POST.


------------------------------ 29. Error behavior ------------------------------


| Подія                            | Реакція на стан                                               | Видимий результат        |
|----------------------------------|---------------------------------------------------------------|--------------------------|
| Активна арифметика видала Error  | Safe B11 = старий Current; після ComputeDone sticky CalcError | POST може встановити 403 |
| M+/M− видали Error               | Safe M = старий Current; після ComputeDone sticky MemError    | POST може встановити 403 |
| Неактивна гілка ALU видала Error | Не вважається worker error                                    | Без впливу               |
| RESULT, Fits=0                   | POST обирає 403                                               | Error Frame              |
| Mode=403                         | Кожна команда крім 305 → DROP                                 | Error Frame              |
| 305 Clear                        | Entry та Arithmetic reset, M без змін, Mode=401               | Entry Frame              |

Публічний worker Error є утримуваним протягом транзакції; raw error безпосередньо не подається на StateController.-in-calcErr/-in-memErr.


------------------------------ 30. Clear і reset behavior ------------------------------


| Дія                  | Entry B6                | Arithmetic B11    | Mode           | M B4            |
|----------------------|-------------------------|-------------------|----------------|-----------------|
| 305 Clear / Flow 504 | Базовий Entry           | DefaultArithmetic | 401 через POST | Без змін        |
| Flow 502 BEGIN_ENTRY | Базовий Entry перед 3xx | Без змін          | 401 через POST | Без змін        |
| 311 MC / Flow 500    | Без змін                | Без змін          | Без змін       | Канонічний нуль |
| Fresh startup        | Базовий Entry           | DefaultArithmetic | 401            | Канонічний нуль |

| Reset type      | Контракт                                                                             |
|-----------------|--------------------------------------------------------------------------------------|
| EntryReset      | Запис явної нульової B6 із LenRaw=0; не плутати відсутність сигналу з нульовою шиною |
| ArithmeticReset | Запис точної DefaultArithmetic B11, включно з Operation=200                          |
| Clear 305       | Не є звичайною командою worker; не повторює InitMemory startup                       |
| M memory        | Clear/BEGIN_ENTRY її не очищують                                                     |


============================== ПРОТОКОЛИ ТА ТРАНЗАКЦІЇ ==============================


------------------------------ 31. SyncBuffer protocol ------------------------------


| Сигнал / стан  | Умова використання / гарантія                                                             |
|----------------|-------------------------------------------------------------------------------------------|
| -out-ready=1   | Може бути прийнятий новий пакет за активного Capture                                      |
| -inB-busData   | Producer забезпечує правильність і ширину даних до прийняття Capture                      |
| -in-capture    | Захоплення лише один раз за Ready; утримуваний Capture не може створювати наступний пакет |
| -out-valid=1   | Заморожений BusOut вже стабільний; споживач може його читати                              |
| -out-valid=0   | BusOut не є авторитетним пакетом                                                          |
| -in-release=1  | Consumer звільняє пакет після обробки; не означає новий Capture                           |
| Capacity       | Рівно один пакет; FIFO/черга відсутня                                                     |
| Ширина payload | Generic B, обраний у екземплярі; шини через BusGate не перевищують 15 слотів              |
| Rearm          | Ready повертається після спаду Capture і Release та очищення внутрішніх блокувань         |

| Протокол | Перехід                                          |
|----------|--------------------------------------------------|
| 1        | Ready → допустимий Capture                       |
| 2        | Захоплення → закриття write і settle             |
| 3        | Valid=1 → consumer використовує BusOut           |
| 4        | Consumer Release → Valid спадає                  |
| 5        | Capture=0, Release=0 → повторна готовність Ready |

Універсальний SyncBuffer має generic bus без фіксованого числа слотів; його інтерфейс не є гарантією семантики payload.


------------------------------ 32. ExecTimer protocol ------------------------------


| Вхід / вихід      | Контракт                                       |
|-------------------|------------------------------------------------|
| -in-start         | Новий фронт Start → один запуск                |
| -in-delay         | Ціле число логічних тіків, Delay ≥ 5           |
| -out-done         | Однотиковий імпульс після заданої затримки     |
| Утриманий Start=1 | Не спричиняє повторних Done                    |
| Наступна робота   | Потребує нового фронту Start (rearm)           |
| Delay < 5         | Поза допустимим контрактом; не використовувати |


------------------------------ 33. FeedbackSynchronizer protocol ------------------------------


| Вхід / вихід | Контракт                                                             |
|--------------|----------------------------------------------------------------------|
| -in-valid    | Стабільний кореневий рівень транзакції, утримуваний до GlobalRelease |
| -in-execute  | Дозвіл даному worker або фазі розпочати виконання                    |
| -in-delay    | Повинен відповідати ExecTimer.Delay ≥ 5                              |
| -out-work    | Активний compute/write window до завершення worker-фази              |
| -out-done    | Однотиковий імпульс завершення таймера                               |
| -out-release | Утримуваний рівень після Done, до Valid=0                            |
| Execute=0    | Не дає права цьому worker звільняти чужу команду                     |
| Valid=0      | Скидає утримуваний Release перед наступною транзакцією               |

Done і Release не взаємозамінні. Release окремого worker не скидає RootValid: право на GlobalRelease має StateController.


------------------------------ 34. Frozen Flow ------------------------------


| Етап                       | Гарантія                                              |
|----------------------------|-------------------------------------------------------|
| Вхід Code, Mode, RootValid | Застосовуються до одного funFlowDecoder               |
| До DecodeDone              | Raw Flow не є авторитетним                            |
| DecodeDelay=20 завершено   | Дозволяється Capture Flow у FlowController.SyncBuffer |
| Flow.Valid=1               | Flow 500…504 заморожено на всю транзакцію             |
| Після Mode commit          | Уже заморожений Flow не переобчислюється              |
| GlobalRelease              | Звільняє FlowBuffer і відкриває шлях до нового Decode |

Публічні виходи FlowController: тільки -out-flow та -out-valid; -out-ready у нього немає.


------------------------------ 35. Transaction protocol ------------------------------


| №  | Фаза          | Умова завершення / наступний крок                                        |
|----|---------------|--------------------------------------------------------------------------|
| 1  | Input Capture | InputController.Valid=1: зафіксований Command B2                         |
| 2  | Decode        | DecodeDelay=20, DecodeDone                                               |
| 3  | Frozen Flow   | FlowController.Valid=1                                                   |
| 4  | PRE           | PrepDelay=20, PreparationController.Ready=1                              |
| 5  | Worker gate   | Для 500/502/503 запуск одного worker; для 501/504 worker не запускається |
| 6  | Compute       | Worker Work=1, формує Candidate; ComputeDone завершує вікно              |
| 7  | Commit        | Work↓, копія Candidate→Current; worker Release після CommitDelay         |
| 8  | POST check    | PostCheckDelay=20, опрацювання sticky worker error і Fits                |
| 9  | Mode commit   | ModeCommitDelay=20, запис TargetMode у ModeCandidate→ModeCurrent         |
| 10 | GlobalRelease | Звільнення Input та Frozen Flow; тільки тепер може завершитися RootValid |

| Маршрут                         | Умова                                                                         |
|---------------------------------|-------------------------------------------------------------------------------|
| RootValid                       | InputController.-out-valid                                                    |
| MainValid                       | RootValid AND FlowValid AND PreReady AND Flow∈{500,502,503}                   |
| WorkerRelease                   | OR EntryRelease, CalcRelease, MemRelease; активним може бути лише один        |
| ExecDone при Flow∈{500,502,503} | WorkerRelease                                                                 |
| ExecDone при Flow∈{501,504}     | PreReady                                                                      |
| Mode target                     | Базовий Mode за Flow; Error у worker або ResultFits=0 при target RESULT → 403 |
| End transaction                 | Не раніше завершення POST та ModeCommit                                       |


------------------------------ 36. Transaction invariants ------------------------------


| Інваріант транзакції    | Контракт                                                             |
|-------------------------|----------------------------------------------------------------------|
| Одна активна транзакція | Одночасно не більше одного Input/Flow пакета                         |
| Один normal worker      | Entry / Calculation / Memory — взаємовиключні команди                |
| Work / Current          | Current не повинен бути перезаписаний, поки Compute Work активний    |
| Worker completion       | WorkerRelease спрацьовує після його commit, не після одного raw Done |
| Frozen Flow             | Незмінний від Flow.Valid до GlobalRelease                            |
| Sticky Error            | Зберігається до кінця RootValid, доступний під час POST              |
| DROP / CLEAR            | Також проходять POST і ModeCommit, хоч normal worker відсутній       |
| MainValid               | Не спадає тільки через WorkerRelease; RootValid далі зберігається    |
| Наступний пакет         | Допустимий тільки після Release та rearm Input SyncBuffer            |

| SRFlag Set | SRFlag Reset | Результат                   |
|------------|--------------|-----------------------------|
| 0          | 0            | Зберегти попередній біт     |
| 1          | 0            | Записати 1                  |
| 0          | 1            | Записати 0                  |
| 1          | 1            | Записати 0 (Reset priority) |


------------------------------ 37. Startup contract ------------------------------


| Startup entity                          | Стан / гарантія                                                      |
|-----------------------------------------|----------------------------------------------------------------------|
| InitMemory                              | Один стартовий імпульс AND(1,NOT(1)); не runtime reset               |
| InitBusMemory                           | Те саме для всіх слотів шини                                         |
| ModeCandidate                           | InitValue=401                                                        |
| ArithmeticCandidate B11                 | InitBus=[0,0,0,0,0,0,0,0,200,0,0]                                    |
| EntryState B6                           | Звичайний фізичний нуль → LenRaw=0 → Len=1                           |
| M B4                                    | Звичайний фізичний нуль → NumberZero                                 |
| Root Valid                              | Input.Valid без InitializationController / InitReady                 |
| Перша команда                           | StartupSettleTime < DecodeDelay=20                                   |
| Зміна InitValue / InitBus після startup | Не переписує вже ініціалізовану пам'ять                              |
| Runtime Clear                           | Не генерує вдруге startup pulse, використовує звичайні reset signals |


============================== АРИФМЕТИЧНІ КОНТРАКТИ ==============================


------------------------------ 38. Number normalization ------------------------------


| Об'єкт                | Умова / гарантія                                                                            |
|-----------------------|---------------------------------------------------------------------------------------------|
| Number B4, ненульовий | 10000 ≤ Hi ≤ 99999; 0 ≤ Lo ≤ 99999; Neg=0/1                                                 |
| Number B4, нуль       | [0,0,0,0]; не допускається -0 як арифметичний Number                                        |
| Entry                 | Не нормалізований; -0 допустимий до funEntryToNum                                           |
| funEntryToNum         | Допустимий Entry → канонічний Number                                                        |
| funMagnitudeOrder     | Порівнює модулі B4 за Exp/Hi/Lo з пріоритетом ненульового Number над нулем; Neg ігнорується |
| funShift25            | shift>0 вправо; shift<0 вліво; abs(shift)≥25 → B5 zero                                      |
| funWideSub25          | Вхідна передумова A≥B, інакше не визначається signed difference                             |
| funAddSub             | Другий знак інвертується для Sub; Big/Small за модулем; зсуви 1 і expDiff+1                 |
| funNormalizeAddSub25  | Виходи Hi/Lo/Exp/zero; знак визначає funAddSub                                              |
| funMul5x5             | Два п'ятизначні chunk, без об'єднання великої мантиси в native scalar                       |
| funMulCore            | Входи 4 chunks Hi/Lo, результат з окремих часткових добутків                                |
| funDivInit            | Обробляє нульовий дільник, але видає dHi≠0 для обчислювального тракту                       |
| funDivQHat            | Передумова dHi≠0; без clamp; у допустимому DivPairStep qHat=0…100                           |
| funDivMulD            | Передумова qHat=0…100 для прийнятого pair pipeline                                          |
| funDivCorrectR        | Передумова: qHat завищений не більш ніж на 1; один correction; 0≤R<D                        |
| funDivPairStep        | Одна двоцифрова пара quotient та наступний залишок                                          |
| funDivCore            | Шість послідовних pair step; q0…q5                                                          |
| funPairsToMantissa    | q0…q4 = десять digits; q5 = guard, round half-up                                            |

Усі арифметичні Number-входи мають відповідати C§8. Не використовувати 10-значне native scalar для Hi|Lo та 25-значне для B5.


------------------------------ 39. Rounding ------------------------------


| Контекст          | Правило                                                                                          |
|-------------------|--------------------------------------------------------------------------------------------------|
| funRound, x≥0     | floor(x+0.5) — half-up                                                                           |
| Number арифметики | Результат — канонічний Number до 10 значущих цифр                                                |
| FIXED             | Точність визначають funPrecision і довжина рядка для фізичних 10 позицій                         |
| SCIENTIFIC        | Точність визначають знак, кількість цифр Exp, знак Exp; враховувати перенесення Exp при rounding |
| SCIENTIFIC Fits   | Результат може не вміститися: Fits=0                                                             |
| Add/Sub           | 25-розрядне вирівнювання, нормалізація й guard для half-up                                       |
| Mul               | 19-/20-значний добуток із нормалізацією та переносом до Exp                                      |
| Div               | П'ять quotient pairs — 10 цифр; шоста — guard для half-up                                        |
| Display-rounding  | Ніколи не записується назад до Result, Operand або M                                             |
| Native round      | Не використовується як правило округлення проєкту                                                |


------------------------------ 40. Arithmetic errors ------------------------------


| Умова                                                            | Error / гарантія                                                                                |
|------------------------------------------------------------------|-------------------------------------------------------------------------------------------------|
| Успішний результат                                               | -999999 ≤ Exp ≤ 999999                                                                          |
| Exp > 999999                                                     | Arithmetic Error                                                                                |
| Exp < -999999                                                    | Arithmetic Error                                                                                |
| Divisor = canonical zero                                         | Division-by-zero Error                                                                          |
| Inactive ALU branch                                              | Її raw error не є worker error                                                                  |
| Прямий виклик ArithmeticUnit з Operation=200 або невідомим кодом | invalidOperation=1 у виході ALU; код 200 допустимий у state, але не як операція для запуску ALU |
| Worker з UseALU=0                                                | RawCalcError маскується, навіть якщо внутрішня inactive ArithmeticUnit формує помилку           |
| Активний worker ALU Error                                        | Candidate замінюється старим Current; публічна помилка фіксується після ComputeDone             |
| RESULT, Fits=0                                                   | Помилка представлення: Error Frame і POST Mode=403                                              |
| Mode=403                                                         | 301…304,306…311 → 501 DROP; 305 Clear → 504                                                     |

Публічна помилка worker утримується до Valid=0; StateController POST не використовує сирий імпульс помилки.


============================== ТАЙМІНГИ ТА ІНВАРІАНТИ ==============================


------------------------------ 41. Logical timing model ------------------------------


| Об'єкт / шлях                                                     | Логічна затримка                                                                |
|-------------------------------------------------------------------|---------------------------------------------------------------------------------|
| Фізичний обчислювальний примітив (Valve, Pass, NOT, AND, OR тощо) | Рівно 1 тік                                                                     |
| Wire / junction / Via / Port                                      | 0 тіків                                                                         |
| Custom Circuit як оболонка                                        | 0 власних додаткових тіків, затримку визначає внутрішній шлях                   |
| Послідовні примітиви                                              | Сума затримок                                                                   |
| Паралельні шляхи                                                  | Критичний шлях — максимальна затримка                                           |
| Константа 1 від Toggle                                            | Немає окремої додаткової обчислювальної затримки                                |
| TPS=N                                                             | N логічних тіків за секунду; зміна TPS масштабує час, не порядок логічних тіків |

| Умова для використання Delay | Контракт                                                              |
|------------------------------|-----------------------------------------------------------------------|
| Worker ComputeDelay          | Не менший від підтвердженого критичного шляху до безпечного Candidate |
| Worker CommitDelay           | Окремо від Compute; завершення Done не дорівнює завершенню commit     |
| FeedbackSynchronizer.Delay   | Вхід ExecTimer; не тотожний повному часу командної транзакції         |
| Не виміряні шляхи            | Не приписувати їм вигаданих окремих latency                           |


------------------------------ 42. Arithmetic latency ------------------------------


Таймінги затверджених F-функцій та зовнішнього ALU-вибору:

| Функція / шлях  | Критична затримка, тіків | Нотатка                           |
|-----------------|--------------------------|-----------------------------------|
| funAdd          | 44                       | через funAddSub(-in-sub=0)        |
| funSub          | 44                       | через funAddSub(-in-sub=1)        |
| funMul          | 28                       | точний chunk-product              |
| funDiv          | 176                      | шість двоцифрових кроків          |
| ArithmeticUnit  | +3                       | вихідний вибір результату/помилки |
| ALU Add Compute | 47                       | 44+3                              |
| ALU Sub Compute | 47                       | 44+3                              |
| ALU Mul Compute | 31                       | 28+3                              |
| ALU Div Compute | 179                      | 176+3                             |

Виміряні допоміжні function-шляхи F (для відновлення критичних шляхів):

| F                    | Тіки | F                 | Тіки |
|----------------------|------|-------------------|------|
| funMagnitudeOrder    | 7    | funMul5x5         | 10   |
| funShift25           | 8    | funMulCore        | 17   |
| funWideAdd25         | 6    | funMulNormalize10 | 7    |
| funWideSub25         | 5    | funDivInit        | 11   |
| funLeadingPosition25 | 5    | funDivQHat        | 4    |
| funNormalizeAddSub25 | 18   | funDivMulD        | 6    |
| funAddSub            | 44   | funDivCorrectR    | 11   |
| funPairsToMantissa   | 9    | funDivNextX       | 6    |
| funDivPairStep       | 27   | funDivCore        | 156  |

Частина display/Entry-функцій у F не має окремо заміряного latency. Не надавати їм вигаданих числових значень; для цих шляхів використовуються консервативні stage windows або окрема перевірка. Абсолютний час реального калькулятора залежить від усієї послідовності фаз, не лише ALU.

| Підсистема/вікно                  | Delay, тіків    | Тип / важливе правило                            |
|-----------------------------------|-----------------|--------------------------------------------------|
| InputController SyncBuffer        | settle-протокол | без окремого fixed worker Delay                  |
| FlowController DecodeSync         | 20              | перед Frozen Flow capture                        |

| EntryController Compute           | 20              | консервативно, не заявлений мінімум              |
| CalculationController non-ALU     | 20              | Operation без ALU / Equals no-op / MR            |
| CalculationController ALU Add/Sub | 47              | F 44 + ALU selection 3                           |
| CalculationController ALU Mul     | 31              | F 28 + ALU selection 3                           |
| CalculationController ALU Div     | 179             | F 176 + ALU selection 3                          |
| CalculationController Commit      | 20              | Current state settle до worker Release           |
| MemoryController Compute M+/M−/MC | 47              | один Delay для всіх трьох команд                 |
| MemoryController Commit           | 5               | мінімальний safe timer delay, перевірено фізично |

Потрібно розрізняти: Function critical latency; ComputeSync.Delay; CommitSync.Delay; і End-to-end тривалість всієї командної транзакції (включно з Decode/Prep/Post та packet settle). Їх не можна підміняти одним числом. MemoryController Commit=5, НЕ 20; в CalculationController Commit=20. Стадії POST/ModeCommit виконуються і в DROP/CLEAR, навіть якщо normal worker пропущений.


------------------------------ 44. Global invariants ------------------------------


| Наскрізне правило                | Нормативний наслідок                                                                      |
|----------------------------------|-------------------------------------------------------------------------------------------|
| Коди                             | Лише визначені у C§2–7; Mode (4xx) не є Flow (5xx)                                        |
| Стани                            | Публічні результати завжди з Current, не з Candidate                                      |
| Normal writers                   | Рівно один normal writer на кожний state bank                                             |
| Command transaction              | Одночасно не більше одного active command packet                                          |
| Flow                             | Заморожений до завершення поточної транзакції                                             |
| Worker                           | Не більше одного normal worker на одну команду                                            |
| Bank atomicity                   | Arithmetic B11 і Memory B4 не можуть commit-итися частинами                               |
| Error                            | Safe Candidate + sticky worker Error; POST після завершення worker                        |
| Reset                            | Clear не змінює M; MC не змінює Arithmetic і Entry                                        |
| Вхід Number                      | Канонічність обов'язкова перед арифметичними функціями                                    |
| Апаратний час                    | Один примітив — один тік; усі stage delays мають бути враховані                           |
| Фізична scene межа               | 23 button inputs; десять Digit (value/dot), окремий Indicator                             |
| Вибір Frame                      | B10 Values і B10 Dots із одного Renderer                                                  |
| wire(...)                        | Фізичне об'єднання дротів; не замінювати на OR або арифметичне додавання                  |
| Одноразова ініціалізація         | Startup InitMemory/InitBusMemory відокремлена від runtime reset                           |
| Невідомий Mode                   | DisplayController використовує Error Frame; невідомий Code → DROP, крім чинного Clear 305 |
| Перевикористання generic BusGate | Ширина не більше 15 слотів, окремий Valve на кожен слот; scalar використовує слот 0       |

Точні публічні порти та фізичні алгоритми Circuit визначені у modules.txt; реалізація кожної fun-функції — у functions.txt.
